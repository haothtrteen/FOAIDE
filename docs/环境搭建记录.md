## 二、与手册 §六 的差异（沙箱现实）

手册配方假设 `dl.google.com` / `github.com` 可达，**本沙箱均被 TLS 阻断**。
所有替代方案都遵循项目自身的镜像策略（与 App 内 `sdk_installer.dart` 完全一致）。

| 手册步骤 | 沙箱实际做法 | 原因 |
|---|---|---|
| Flutter tarball ← `storage.flutter-io.cn` | 同左，**1.58GB @ 高速** | 镜像可达 ✅ |
| cmdline-tools ← `dl.google.com` | ← `mirrors.cloud.tencent.com/AndroidSDK/` | dl.google.com 不可达 |
| JDK 17 ← TUNA Adoptium | 同左，**193MB** | 镜像可达 ✅ |
| Android 组件 ← `sdkmanager`（走 dl.google.com） | 改为**直接 curl 腾讯云镜像 + SHA-1 校验** | sdkmanager 报 `Failed to download any source lists!` |
| `flutter version check` ← github | 静默失败但版本正常读取 | github 不可达 |

> **重要发现**：`sdkmanager` 完全不可用（其清单源走 dl.google.com）。
> 但项目 `sdk_installer.dart` 里**已经写死了这 4 个组件的直链、大小和 SHA-1**，
> 直接照抄即可 —— 这正是「App 端自己实现下载器」的价值，服务端反而复用了它。

## 三、踩到的 4 个真实问题（均已解决）

### 1. 预装的 Flutter 是 3.0.0，不是 3.47.4

沙箱自带 `/opt/flutter` 为 **Flutter 3.0.0**（2022-05 构建），远低于项目要求。

```
处理：mv /opt/flutter /opt/flutter_3.0.0.bak   # 保留备份
tar xf flutter_347.tar.xz -C /opt              # 装入 3.47.4
```

验证：`flutter --version` → `Flutter 3.47.4 • Dart 3.13.3` ✅

### 2. `init.gradle` 与项目的 PREFER_SETTINGS 模式冲突 ⚠️ 最有价值的一条

**症状**：
```
Error resolving plugin [id: 'dev.flutter.flutter-plugin-loader', version: '1.0.0']
> Build was configured to prefer settings repositories over project repositories
  but repository 'maven' was added by settings file 'settings.gradle.kts'
```

**根因**：`android/settings.gradle.kts` 的 `pluginManagement {}` 块里已声明 `repositories`
（阿里云镜像 + 官方兜底），Gradle 因此进入 **PREFER_SETTINGS 模式**。
此时 `init.gradle` 里任何 `allprojects { repositories { ... } }` 都会被拒绝。

**但**：`settingsEvaluated` 又覆盖不到 **composite build**
（`/opt/flutter/packages/flutter_tools/gradle`，它是 `includeBuild` 进来的独立构建，
自己的 `settings.gradle.kts` 写死 `google() + mavenCentral()` +
`repositoriesMode = FAIL_ON_PROJECT_REPOS`）→ `kotlin-gradle-plugin:2.0.0`、
`kotlinx-serialization-json:1.4.0` 解析失败。

**正解**：只用 `beforeSettings`（它对主构建和所有 included build 都生效），
且在闭包内**不引用外部 `def` 变量**（Groovy 作用域不跨越该边界）：

```groovy
beforeSettings { settings ->
    settings.pluginManagement.repositories {
        maven { url 'https://maven.aliyun.com/repository/public' }
        maven { url 'https://maven.aliyun.com/repository/google' }
        maven { url 'https://maven.aliyun.com/repository/gradle-plugin' }
        maven { url 'https://maven.aliyun.com/repository/central' }
    }
    settings.dependencyResolutionManagement.repositories {
        maven { url 'https://maven.aliyun.com/repository/public' }
        // ... 同上 4 个
    }
}
```

> 完整文件见 `~/.gradle/init.gradle`（已附注释说明两个构建的关系）。

### 3. Flutter 默认 `ndkVersion` 触发自动下载

`android/app/build.gradle.kts` 里 `ndkVersion = flutter.ndkVersion`
→ Flutter 默认 `28.2.13676358` → AGP 尝试自动下载 NDK → 失败。

虽然本项目**无任何 native 代码**（无 `.c/.cpp/CMakeLists.txt`），
但为**不修改源码**，仍从腾讯镜像装齐 NDK：

```bash
curl -L -o ndk.zip "https://mirrors.cloud.tencent.com/AndroidSDK/android-ndk-r28b-linux.zip"  # 722MB
unzip -q ndk.zip -d ndk && mv ndk/android-ndk-r28b ndk/28.2.13676358
```

### 4. AGP 的 SDK 探测噪声（可忽略）

构建期会打印大量 `Warning: IO exception while downloading manifest` /
`SSLHandshakeException` —— 这是 **AGP 的自动 SDK 补全探测**在访问被阻断的
`dl.google.com`。**属 warning，不阻断构建**（与最终 BUILD SUCCESSFUL 并存）。
