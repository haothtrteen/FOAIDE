# 01 · 环境搭建

> 开发机环境 + 项目初始化 + 真机调试配置

## 〇、仓库结构与 Git 工作流

### 两个独立仓库（与许可证架构对应）

| 仓库 | 内容 | 可见性 | 许可证 |
|---|---|---|---|
| `app/` | IDE 核心代码（编辑器、构建编排、插件宿主） | **将来开源** | AGPL-3.0 |
| `dev-handbook/` | 开发手册（含商业模式、加固策略等敏感内容） | **永久私有** | 不分发 |

> ⚠️ `dev-handbook` 永远不进开源仓库——里面有商业化策略和加固对抗细节。

### Git 约定

- 分支：`main`（稳定）+ `dev`（日常开发，可选）；
- 提交信息：`类型: 描述`，类型用 `feat / fix / docs / chore / refactor / test`；
- **每个 Step 真机验证通过后打 tag**：`git tag step1-ok && git push origin main --tags`；
- 二进制资产（proot、rootfs tarball）**不进 git**，clone 后先跑 `tools/fetch_assets.sh`；
- 后续新增 `plugin-sdk/`（MIT）和 `backend/`（专有）时各建独立仓库。

### 同步到 GitHub（首次）

```bash
# app 仓库 → 公开仓库
cd app
git remote add origin git@github.com:<你的用户名>/<项目名>.git
git push -u origin main --tags

# dev-handbook → 私有仓库
cd dev-handbook
git remote add origin git@github.com:<你的用户名>/<项目名>-docs.git
git push -u origin main
```

## 〇.5、Step 1 关键架构决策（2026-09-16 定稿）

| 决策 | 结论 | 原因 |
|---|---|---|
| 进程通信 | MethodChannel → Kotlin ProcessBuilder | Dart 侧 Process.start 不可靠；原生层统一管理进程生命周期与流读取 |
| targetSdk | **28**（Termux 同款方案） | Android 10+ W^X 限制：targetSdk≥29 禁止 execve() 数据目录二进制，而 rootfs 内 guest 二进制由内核真实执行。代价：无法上 Play（本来就不上，走 GitHub/F-Droid） |
| proot 部署 | jniLibs `libproot.so` 优先 + assets 兜底 | 原生库目录不受 W^X 限制；双保险（见 Bug 104） |
| proot loader | `PROOT_LOADER` 环境变量指向 `filesDir/tools/loader` | Termux 构建的 proot loader 路径硬编码为 com.termux 包；实测 proot 认该环境变量，**无需重编译 proot** |
| rootfs 来源 | 服务器侧 debootstrap minbase（arm64）构建，tarball 内置于 assets | 75MB minbase（bookworm，apt 可用），比 LXC 镜像（91MB 且含 systemd）更贴需求 |
| 服务器同步验证 | `tools/devbox_test.sh`：x86_64 proot 原生 + qemu-aarch64 翻译 guest | 与真机共用同一 rootfs tarball；服务器预验证 rootfs 层，真机覆盖 ptrace/内核层（见 app/SETUP_ANDROID.md） |
| rootfs 解压 | 系统自带 toybox tar | 必须保留 Unix 权限位与符号链接，Dart archive 包不保证 |
| 日志 | JSONL 结构化（`filesDir/logs/`） | 每条命令记 exitCode/stdout/stderr/durationMs，Bug 排查的证据链 |
| android/ 壳 | 由 `setup_android.sh` 生成后入库 | Gradle/AGP 版本需与本机 Flutter 匹配，手写易踩兼容坑 |

工程细节详见 `app/SETUP_ANDROID.md`。

## 一、开发机环境（桌面端）

## 二、项目初始化

### 仓库结构

```
app/                     # Flutter App 主工程（AGPL-3.0）
  lib/
    core/                # 编辑器、文件树、通用组件
    env/                 # proot 管理、rootfs 组装
    builder/             # 构建编排器
    plugins/             # 插件宿主与 SDK
    ui/                  # 页面与导航
  android/               # 安卓原生层
  assets/
    rootfs/              # rootfs 相关资源（运行时下载，不内置）
    tools/               # 预编译的 arm64 工具（aapt2、proot 等）
plugin-sdk/              # 插件 SDK（MIT，独立仓库或子模块）
backend/                 # 商城后端（专有，私有仓库）
dev-handbook/            # 本手册
```

### 初始创建命令（实际流程，Step 1 已落地）

```bash
cd app
flutter pub get
./tools/fetch_assets.sh      # 下载 proot + rootfs 资产（不进 git）
./tools/setup_android.sh     # flutter create + 应用定制 + targetSdk 28 + jniLibs
./tools/check_env.sh         # 自检：资产/架构/targetSdk/设备
flutter run
```

> 包名固定为 `dev.foa.flutter_on_android`（`--org dev.foa`）。开源前确定品牌名，改包名成本高，别拖到 Step 3 之后。

### 原生权限

`android/app/src/main/AndroidManifest.xml` 需添加：

```xml
<!-- 网络：下载 SDK、Pub 依赖 -->
<uses-permission android:name="android.permission.INTERNET"/>
<!-- 存储：访问项目文件（Android 10+ 用 scoped storage） -->
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE"/>
<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE"
    android:maxSdkVersion="28"/>
<!-- 请求安装 APK -->
<uses-permission android:name="android.permission.REQUEST_INSTALL_PACKAGES"/>
<!-- 前台服务：构建时保活 -->
<uses-permission android:name="android.permission.FOREGROUND_SERVICE"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_SPECIAL_USE"/>
```

## 三、真机调试配置

### 手机端准备

1. 开启"开发者选项" → 打开"USB 调试"；
2. （推荐）打开"无线调试"，摆脱数据线；
3. 关闭"电池优化"中对本 App 的优化，避免构建时被杀。

### 连接方式

```bash
# USB 连接
adb devices

# 无线调试（Android 11+）
# 手机端：开发者选项 → 无线调试 → 使用配对码配对
adb pair <ip>:<port>
adb connect <ip>:<port>
```

### 常用调试命令

```bash
# 查看日志（过滤 Dart/Flutter 相关）
adb logcat | grep -E "flutter|Dart|AndroidRuntime"

# 查看应用内存
adb shell dumpsys meminfo <package_name>

# 查看电池/温度（构建压力测试用）
adb shell dumpsys battery
adb shell cat /sys/class/thermal/thermal_zone*/temp

# 安装/卸载 APK
adb install -r build/app/outputs/flutter-apk/app-debug.apk
adb uninstall <package_name>

# 将文件推送到手机（测试 rootfs 等大文件时用）
adb push local_file /sdcard/
```

## 四、测试设备矩阵建议

| 档位 | 推荐机型参考 | Android 版本 | RAM | 目的 |
|---|---|---|---|---|
| 入门机 | 骁龙 6xx / 天玑 7xx 机型 | 9-10 | 4GB | 验证性能下限、OOM 风险 |
| 主力机 | 骁龙 8 Gen 1/2 | 13-14 | 8-12GB | 日常开发调试 |
| 旗舰机 | 最新骁龙 / 天玑旗舰 | 15-16 | 12GB+ | 验证性能上限、AVF 兼容性 |

## 六、环境重建速查（2026-09-17 沙箱重置后实测）

> 沙箱/开发机重置后 SDK 全丢，按此顺序 5 分钟恢复（全程国内镜像，约 1.9GB 下载）。

```bash
# 1. Flutter 3.47.4 stable（约 1.5GB，30MB/s+）
curl -L -o /tmp/flutter.tar.xz "https://storage.flutter-io.cn/flutter_infra_release/releases/stable/linux/flutter_linux_3.47.4-stable.tar.xz"
tar xf /tmp/flutter.tar.xz -C /opt

# 2. git 权限（flutter 内部工具依赖 git，首次运行报 dubious ownership）
git config --global --add safe.directory /opt/flutter

# 3. Android cmdline-tools（约 146MB）
mkdir -p /data/user/work/sdk && cd /data/user/work/sdk
curl -L -o cmdtools.zip "https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip"
unzip -q cmdtools.zip -d cmdline-tools && mv cmdline-tools/cmdline-tools cmdline-tools/latest

# 4. 开发机 JDK 17（坑：sdkmanager 需 class file 61.0，系统 JDK 11 报
#    UnsupportedClassVersionError；apt 源可能不可用 → 直接下 Temurin x64）
curl -L -o /tmp/jdk17.tar.gz "https://mirrors.tuna.tsinghua.edu.cn/Adoptium/17/jdk/x64/linux/OpenJDK17U-jdk_x64_linux_hotspot_17.0.20.1_1.tar.gz"
mkdir -p /opt/jdk17 && tar xzf /tmp/jdk17.tar.gz -C /opt/jdk17 --strip-components=1

# 5. 装 Android 组件（JAVA_HOME 指向 17！）
export JAVA_HOME=/opt/jdk17 ANDROID_HOME=/data/user/work/sdk
cd $ANDROID_HOME/cmdline-tools/latest/bin
(yes | ./sdkmanager --licenses)
./sdkmanager "platform-tools" "build-tools;36.0.0" "build-tools;35.0.0" "platforms;android-36"

# 6. 配置 flutter 与项目 local.properties
export PUB_HOSTED_URL=https://pub.flutter-io.cn FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
/opt/flutter/bin/flutter config --android-sdk /data/user/work/sdk
printf 'flutter.sdk=/opt/flutter\nsdk.dir=/data/user/work/sdk\n' > app/android/local.properties

# 7. 环境变量固化（之后每次 source 即可）
cat > /data/user/work/env.sh <<'EOF'
export PATH=/opt/flutter/bin:$PATH
export PUB_HOSTED_URL=https://pub.flutter-io.cn
export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
export ANDROID_HOME=/data/user/work/sdk
export JAVA_HOME=/opt/jdk17
EOF
```

**验证**：`flutter doctor` → `[✓] Android toolchain` 即恢复完成。

## 七、CI/CD 环境（GitHub Actions）

公共仓库免费使用 arm64 跑机（`ubuntu-24.04-arm`），用于构建管线的自动化回归测试。工作流文件放在 `.github/workflows/` 下，至少包含：

- `lint_test.yml`：静态检查 + 单元测试（每次 push）
- `build_apk.yml`：构建 community flavor APK（PR 和 tag）
- `arm_smoke.yml`：arm64 runner 上跑 proot + flutter build 冒烟测试（每天定时 + tag）
- `license_scan.yml`：ScanCode 许可证扫描（每次引入新依赖时手动触发 + 每周定时）
