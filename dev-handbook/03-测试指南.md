# 03 · 测试指南

> 12 步真机验证法 + 性能基线 + CI 门禁
>
> 核心原则：**每完成一个最小可验证单元，就在真机上跑通一次**。不攒代码、不堆功能、不硬撑。

## 一、每步完成定义（DoD）

每一步必须满足以下 4 条才算通过，少一条不进入下一步：

1. **功能跑通**：达到该步的验证标准（真机实测）；
2. **日志可见**：所有错误有清晰的 UI 展示，不是黑屏/闪退；
3. **有回退 tag**：`git tag stepX-ok`，随时能切回去；
4. **CI 过门禁**：该步对应的自动化测试通过（如已有）。

## 六、远程接管（alpha.60）真机验证清单

这个功能本质上是**把设备变成一个可被远程访问的 RCE 端点**。常规功能
"能跑就行"，这里不行——每一条安全边界都得实测确认：

**安全边界（最重要，任何一条不过就不能发）**

- [ ] **未开启时** 8977 端口在回环外不可达：同一局域网另一台设备
      `curl http://<手机IP>:8977` 必须超时或拒绝连接（只绑 127.0.0.1
      是本功能最重要的边界，**任何时候都不要改成 0.0.0.0**）
- [ ] 不带令牌请求返回 **401**；带错令牌同样 401
- [ ] 手动停止后，旧令牌立即失效（再请求 401）
- [ ] 隧道 30 分钟到期自动停止（对外窗口应尽量短）

**功能**

- [ ] 开启后拿到 `*.trycloudflare.com` 地址 + 令牌，一键复制的接入
      说明能被远端 AI 直接用上（含 `/mcp` 路径与鉴权头写法）
- [ ] `tools/list` 返回 **7 个工具**，且**不含 build_apk**
- [ ] `foa_diag` 返回内容与人工点「故障诊断」一键执行的结果一致
- [ ] `read_file` / `write_file` 走 FsBridge（Kotlin 文件通道），
      **不占 proot executor**——远程读写时本地构建不卡
- [ ] 并发两条命令 → 第二条返回 `DeviceBusy`（不排队，用户自己的
      操作不会被莫名卡住）

**审计与可观测**

- [ ] 被拒绝的命令（`rm -rf /`）也要出现在审计日志里
- [ ] 审计日志在 UI **实时**可见（这是用户的监督窗口，不是日志收纳）

**cloudflared**

- [ ] `cloudflared --version` 在容器内正常输出（确认是 **arm64**
      资产；amd64 版会走 QEMU 转发，又慢又脆）
- [ ] 停止后容器内无残留隧道进程

> 判读提示：`--version` 幂等探活失败、或下载后仍起不来，先看
> `/opt/foa-bin/` 下文件的可执行位——宿主侧没有 chmod 权限，必须靠
> 容器内 `chmod 755` 补上。

## 七、静态断言型单测的写法（alpha.61/62 起的约定）

`test/` 里有相当一部分用例**不构造 widget、不跑流程**，而是读源码字符串
做断言（`manifest_page_test.dart` / `build_panel_test.dart` /
`proroot_integration_test.dart` / `blank_project_template_test.dart`）。
这不是偷懒，而是这类约束的**唯一可测形态**，但要按规矩写。

### 7.1 什么时候该这么写

| 约束类型 | 例子 | 为什么不能用行为测试 |
| --- | --- | --- |
| 跨文件常量同源 | `#F5F7F8` 同时存在于 Dart / Kotlin / XML | 三处无法在一个测试进程里同时实例化 |
| 数据源单一 | 阶段清单必须来自 `BuildStages.ordered` | 行为上"看起来一样"，只有结构能验 |
| 顺序耦合 | `IndexedStack.children` 必须与枚举同序 | 需要真机渲染才能暴露，代价过高 |
| 危险操作的护栏 | 删缓存前必须有二次确认 | 真的去删太危险 |
| 协议字段对齐 | Dart 传 `'proroot'` ↔ Kotlin 读 `"proroot"` | 跨语言，没有编译器保护 |
| 硬编码审计 | 代码行不出现 `com/example/` 字面量 | 本身就是"源码里有没有"的问题 |

### 7.2 三条写法纪律

1. **断言要贴着实际写法**。例：`_buildSections()` 里打包区是通过
   转发方法 `_buildPanel()` 落位的，而不是直接构造 `BuildPanel(`。
   断言 `'BuildPanel('` 会**假失败**。改断言而不是改代码——结构没错。
   > 上线前真的踩到了这条：断言写 `BuildPanel(`，
   > 报 `Expected: <9> Actual: <-1>`。

2. **注释行不算**。审计"没有硬编码"时要跳过 `#` / `//` 开头的行，
   否则**注释里举的例子**会把断言打红。例：`com/example/` 出现在
   解释性注释里是正常的。

3. **每个断言带 `reason:`**。静态断言失败时光看 `Expected: false
   Actual: true` 完全不知道自己破坏了什么，`reason` 要把
   **"为什么这条约束重要"**写清楚（最好带上用户会看到的现象）。

### 7.3 与行为测试的分工

- 能跑真逻辑的就跑真逻辑：`manifest_codec_test.dart`（34 项）、
  `project_stats_test.dart`（15 项）都是**纯函数抽取后逐条单测**，
  这是首选做法；
- 只有在"无法实例化 / 跨进程 / 危险"时才退回静态断言；
- **静态断言不能替代真机验证**。`blank_project_template_test.dart`
  里有 `dash -n` 语法检查（真跑 dash），比纯字符串比对强一级。

### 7.4 跨语言键名契约：最脆的一类接口

Dart 与 Kotlin 之间走 MethodChannel 传 map，**两侧都是字符串字面量**，
编译器完全不参与。这类接口的失效模式很特别：

| 失效模式 | 为什么难发现 |
| --- | --- |
| 键名拼错（`"error"` vs `"stderr"`） | 不报错，读到 `null`，UI 显示兜底文案 |
| 返回 map 缺键 | 同上，且 Dart 的 `as String?` 把它悄悄变成 `null` |
| 两侧类型观不一致 | Kotlin 编译期才报（见 Bug 460），Dart 侧完全无感 |

**写法**：在 `test/` 里**从 Dart 侧反查**——先定位 `factory XxxResult.fromMap`
读的键，再断言 Kotlin 那个方法体内确实产出了这些键。

```dart
// 1) Dart 读什么
final at = models.indexOf('factory ProrootProbeResult.fromMap');
final body = models.substring(at, at + 500);
for (final k in ['ok', 'exitCode', 'output', 'cmd', 'error']) {
  expect(body.contains("m['$k']"), isTrue);
}
// 2) Kotlin 就得给什么
final ps = kt.indexOf('private fun prorootProbe(');
final pe = kt.indexOf('private fun applyProrootEnv('); // 下一个方法作为右界
final pbody = kt.substring(ps, pe);
for (final k in ['ok', 'exitCode', 'output', 'cmd', 'error']) {
  expect(pbody.contains('"$k" to '), isTrue,
      reason: 'prorootProbe 没有产出 "$k"，Dart 侧会永远读到 null');
}
```

**注意**：`fromMap` 用 `as String?` 这类**软转换**时，缺键和空值无法区分，
所以"键存在"这件事只能靠断言守，不能靠运行时报错。

> Bug 460 就是这条的实例：`return built.error!!` 返回的是 `fail()` 的形状
> （`exitCode`/`stdout`/`stderr`），而 Dart 读 `error`。错配安静地编译
> 通过了——直到 Kotlin 因为另一处类型问题报错，才顺带暴露出来。

**另一条相关纪律**：Kotlin 侧**没有单测框架**，所以"Kotlin 代码能否编译"
只能靠 `compileDebugKotlin`。而这类跨语言签名改动**往往连锁**——
改一个共用构造器的返回类型，会牵出所有消费它的地方。所以：

- 改 Kotlin 的签名后，**预期会有第二轮 e:**，不要以为改一处就完事；
- 看到 `a ?: b` 报 `Any` 而不是预期类型时，通常意味着**左值被放宽了**
  （比如从 `Map<String,Any>?` 变 `Map<String,Any?>?`），
  此时该做的是"从左值里取字段"而不是整个值当其他类型用。

#### 7.8.1 先写断言、确认它红，再动实现（本轮唯一一次做对的事）

需求 A 的 bug 是"接线漏了一处"：`_treeRow(node, depth)` 的 `depth` 参数、
缩进、展开箭头、`_collapsed` 折叠状态**全都写好了**，但 `_treePanel` 里写的是

```dart
children: [_treeRow(_root, 0)]   // ← 只放了根节点
```

编译得过、运行不抛异常、树里永远只有一行。**没有任何一层能发现它**，
除非有人写一条"children 必须递归展开"的断言。

做法：

```bash

flutter test test/design_wiring_test.dart
# → 3 条全 [E]，证明这三条是护栏不是同义反复
# 2. 再改实现
# 3. 复跑 → 17/17 绿
```

**这一步不能省。** 直接"加断言 + 改实现 + 一起跑绿"的话，你无法区分
"断言真的会拦"和"断言恰好和实现撞对了"。这也解释了为什么
`design_wiring_test.dart` 整个文件都是**源码级**断言 ——
它要拦的正是"编译得过但功能静默失效"这一类。

> ⚠️ 折叠状态那一条的**写法**很关键：必须是 `if (_collapsed.contains(node.id)) return rows;`
> 而不是"跳过不画但继续递归"。后者会让子节点的行照样生成、只是被藏起来，
> 展开时行数对不上。断言用正则精确匹配 `return rows;` 就是为了钉死这一点：
>
> ```dart
> expect(RegExp(r'if \(_collapsed\.contains\(node\.id\)\)\s*return rows;')
>     .hasMatch(body), isTrue, reason: '折叠要提前 return，不能只跳过不画');
> ```

#### 7.8.2 本轮踩到的**测试写法**坑（都表现为假红，浪费了大把时间）

**① `code()` 会剥掉注释，于是注释里的关键字不能当断言目标。**

`design_wiring_test.dart` 的 `code()` 剥掉所有 `//` 行（§7.6 第 1 条）。
而本轮源码里有这么一段：

```dart
// ⚠️ 用 `.dart.bak` 而不是 `.bak`：……
final backup = '$_importedPath.bak';
```

断 `expect(page.contains('.dart.bak'), isTrue)` **恒假** ——
唯一出现 `.dart.bak` 的地方是注释。要断的是**实际代码**：

```dart
expect(page.contains("'\$_importedPath.bak'"), isTrue);  // 注意 $ 要转义
```

**② `'$_$f'` 不是"字面量 `$_` 加变量 f"**，而是一个名叫 `_` 的变量 ——
直接编译错 `Undefined name '_'`。要写 `reason: '缺 $f'`。

**③ 跨行的相邻字符串字面量在源码里是分开的，整句 `contains` 恒假。**

```dart
Text(
  '覆盖 ${_importedPath.split('/').last} 会把它的'
  '业务逻辑、状态管理、路由全部替换掉，只剩静态界面。',
```

源码里这**不是**一整句（中间有 `'` `'`）。断言得按分片来：

```dart
expect(page.contains('会把它的'), isTrue);
expect(page.contains('业务逻辑、状态管理、路由全部替换掉'), isTrue);
```

**④ `indexOf` 返回 -1 时，`greaterThan` 会假绿。**

```dart
final write = body.indexOf('bridge.write(');
expect(write, greaterThan(show));   // ← -1 < show 恒成立！
```

"写盘语句被删光了"这种**最该拦的情况**反而通过了。要显式判 `-1`：

```dart
expect(write, -1, reason: '_export 里不该再有写盘');
```

**⑤ `substring(i, i + N)` 的窗口开太大，会把下一个方法吃进来。**

`_applyImport` 后面紧跟 `_showNotesSheet`，窗口取 1400 字符时
`_showNotesSheet` 里的代码会混进"失败路径在前、替换在后"的位置比较，
断言测的就是错的对象。取 **700**（刚好覆盖 `_applyImport` 全体）才对。

同时：**取下标前先断 `i >= 0`**，否则 `substring(-1, ...)` 抛
`RangeError: Invalid value: Not in inclusive range 0..50687: -1` ——
错误信息完全指不到根因，看起来像"文件的字符数不对"。

#### 7.8.3 导入功能的验收：又是"字符串断言看不见编译不过"

`design_import_test.dart` 的 46 条全绿，**只说明字符串层面正确**。
真正的验收必须把**导入 → 生成**的产物喂给 `flutter analyze`：

```bash
# 写个探针把这条路真跑一遍（探针放 lib/ 下才有 package resolution）
dart run lib/_gencheck/gen_probe.dart
flutter analyze lib/_gencheck/raw_imported.dart
```

实测结果（写实的 `LoginPage`，12 个组件 + 3 个未识别）：

- **`clean.dart`（把占位换成合法表达式）→ `No issues found!` 之外的
  只有 4 条 `prefer_const_constructors`**，**零 error** ——
  证明"我们生成的容器结构"本身合法
- **`raw_imported.dart`（真产物）→ 恰好 3 条 error**，全是
  `ThirdPartyLoginRow` / `_onThirdParty` / `kShowAgreement` ——
  这些名字**原文件作用域里本来就没导入**，正是"占位节点原样带回"的
  应有之意。error 数为 **0** 也说明"认出来的那 12 个组件生成的骨架"没问题

> 判据：**error 必须全部落在"原文件依赖的外部名字"上**。
> 出现别的 error（比如括号不配平、逗号缺失、类型不匹配），
> 就是生成器或导入器的真 bug，不能当成"预期内"放过。
>
> 验完 `rm -rf lib/_gencheck/`，别留在仓库里。

#### 7.8.4 一条既有断言正确地变红了

给 `DesignComponentType` 加 `unknown` 成员后，
`design_model_test.dart` 里这条**既有**断言报红：

```dart
test('只有 root 与 card 接受子节点', () {
  expect(accepting, {DesignComponentType.root, DesignComponentType.card});
});
```

这正是它存在的意义（`acceptsChildren` 决定树上能不能往里放东西）。
处理方式不是删掉，而是**改成三方集合**并写明理由：

```dart
expect(accepting, {
  DesignComponentType.root,
  DesignComponentType.card,
  DesignComponentType.unknown,   // 占位节点可能包着一整棵子树
});
```

**顺带补了一条哨兵断言**（本次教训）：组件库网格用的是
`for (final t in DesignComponentType.values)` —— 加枚举成员时它会
**自动**出现在组件库里，"点了没用"的按钮不报错、不警告。所以：

```dart
test('unknown 不出现在组件库里能点的地方', () {
  final page = File('lib/project/design_page.dart').readAsStringSync();
  expect(RegExp(r'DesignComponentType\.unknown').allMatches(page).length,
      greaterThanOrEqualTo(3));
  expect(page.contains('if (t != DesignComponentType.root &&'), isTrue);
});
```

> 📌 **给枚举加成员时的检查清单**（本轮实测，5 处 switch + 易漏点）：
> `label` / `iconName` / `defaultProps` / `fields` / `acceptsChildren` /
> 生成器 `_build` / 预览 `_buildPreview` / 树摘要 `_nodeSummary` /
> 类型图标 `_typeIcon` / **组件库网格的排除条件**。
> 前几个漏了编译器会拦，**最后一个是静默的**。
