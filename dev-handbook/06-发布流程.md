# 06 · 发布流程

> 版本号规则、发布检查清单、回退策略

## 一、版本号规则

采用语义化版本（SemVer）：`主版本.次版本.修订版本`

| 版本类型 | 说明 | 示例 |
|---|---|---|
| 主版本 | 重大架构变更、不兼容的 API 改动 | 1.0.0, 2.0.0 |
| 次版本 | 新增功能、向下兼容 | 1.1.0, 1.2.0 |
| 修订版本 | Bug 修复、性能优化 | 1.0.1, 1.0.2 |

### 版本后缀

| 后缀 | 含义 | 示例 |
|---|---|---|
| `-alpha.N` | 内部测试版，功能不完整 | 0.1.0-alpha.1 |
| `-beta.N` | 公开测试版，功能基本完整 | 0.5.0-beta.2 |
| `-rc.N` | 发布候选版 | 1.0.0-rc.1 |
| 无后缀 | 正式发布版 | 1.0.0 |

### Flutter 版本对应

App 内置的 Flutter SDK 版本与 App 版本独立管理，在 `关于` 页同时显示：

```
App 版本：0.1.0-alpha.1
内置 Flutter：3.24.0-stable
```

每次 Flutter SDK 大版本升级（如 3.22 → 3.24），App 次版本号 +1。

## 二、发布检查清单

### A. 功能检查（必做）

- [ ] 12 步真机测试全部通过（见 03-测试指南.md）
- [ ] 性能基线与上一版对比，退化不超过 20%
- [ ] 入门机（4GB）不 OOM、不闪退
- [ ] 构建功能：debug + release 均正常
- [ ] Web 预览 + 热重载正常
- [ ] 项目创建 / 导入 / 删除正常
- [ ] 存储管理 / 清理功能正常
- [ ] 横竖屏切换 / 平板适配无明显错乱

### B. 质量检查（必做）

- [ ] `flutter analyze` 无 error（warning 尽量少）
- [ ] `flutter test` 全部通过
- [ ] CI 全部绿灯
- [ ] 无已知的 crash 级 bug（bug 库中 P0 全部关闭）
- [ ] ANR 率 < 0.5%（有统计的版本）

### C. 许可证合规（必做）

详见 [05-许可证合规.md](./05-许可证合规.md) 第五节"分发合规检查"。

- [ ] LICENSE 文件正确
- [ ] THIRD-PARTY-NOTICES 完整
- [ ] 专有代码未混入 community flavor
- [ ] Google SDK 组件不内置
- [ ] GPL 组件源码链接齐全

### D. 发布物料

- [ ] 更新 `CHANGELOG.md`
- [ ] 更新版本号（`pubspec.yaml` + `build.gradle`）
- [ ] release APK 签名正确（release keystore）
- [ ] GitHub Release 描述包含：更新内容、已知问题、下载链接
- [ ] 官网 / 下载页更新

## 三、发布步骤

### Community 版（GitHub Releases + F-Droid）

```bash
# 1. 切到 release 分支
git checkout main
git pull

# 2. 更新版本号
# 编辑 pubspec.yaml: version: 0.1.0-alpha.1+1
# 编辑 android/app/build.gradle 中的 versionName / versionCode

# 3. 更新 CHANGELOG.md

# 4. 提交并打 tag
git add .
git commit -m "release: 0.1.0-alpha.1"
git tag v0.1.0-alpha.1
git push origin main --tags

# 5. CI 自动构建 community flavor APK
# 等待 Actions 完成

# 6. 下载 CI 产出的 APK，本地验证
# - 安装正常
# - 版本号正确
# - 核心功能跑通

# 7. 发布 GitHub Release
# - 填写更新日志
# - 上传 APK
# - 标记为 Pre-release（alpha/beta 阶段）

# 8. F-Droid 提交流程（首次发布后后续自动更新）
```

### Official 版（官网 + 国内分发渠道）

```bash
# 1. 在 official 分支上合并 main
git checkout official
git merge main

# 2. 合并专有模块
# （确保 proprietary 子模块/仓库已更新到对应版本）

# 3. 构建 official flavor
flutter build apk --flavor official --release

# 4. 验证官方版独有功能
# - 商城登录
# - 付费插件购买流程
# - 加固插件功能

# 5. 签名 + 对齐
# （CI 中配置 release keystore）

# 6. 上传到分发渠道
# - 官网下载页
# - 国内应用市场（如有）
# - 蒲公英 /  Fir 测试分发
```

## 四、回退策略

### 快速回退（5 分钟内）

发现线上严重问题时：

1. GitHub Releases 下架当前版本，指向上一个稳定版；
2. 官网下载链接回退到上一版；
3. 社区公告说明问题和临时解决方案；
4. App 内如果有更新检查，回退推荐版本。

### 热修复（小问题）

- 纯 Dart bug：如果影响面小且有 workaround，等下一个修订版本；
- 原生层 bug：视严重程度决定是否发修订版；
- **构建管线 bug**：优先发修订版，因为这是核心能力。

### 紧急修复流程

```
发现严重 bug → 开 hotfix 分支 → 修复 → 本地验证 → 
打修订版本 tag → CI 构建 → 快速验证 → 发布 → 公告
```

## 五、CHANGELOG 格式

```markdown
## [0.1.0-alpha.1] - 2026-09-16

### 新增
- proot + Debian rootfs 环境安装器
- 代码编辑器（Dart 语法高亮）
- Web 预览（热重载）
- Debug APK 本地构建

### 已知问题
- release 构建在 4GB 内存手机上可能 OOM
- 部分带 native 插件的项目无法构建（NDK 未支持）
- 首次环境下载较慢（国内镜像已优化）
```

## 六、发布节奏建议

| 阶段 | 频率 | 说明 |
|---|---|---|
| Alpha（0.x） | 每 2-4 周一个小版本 | 功能快速迭代，不保证稳定性 |
| Beta | 每月一个版本 | 功能基本完整，侧重打磨 |
| 1.0 后 | 每 6 周一个次版本 + 按需修订版 | 稳定迭代 |
